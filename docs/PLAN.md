# Headless Process Portal - plan (started 2026-09-10)

A standalone Angular application that replicates every function of IBM Process Portal (BAW 8.6.2 / responsive portal) in an
elegant, fully headless way: no coach is ever rendered, the task user interfaces are Angular forms driven by a form contract
carried in the task data. Two runtime modes share one code base:

| Mode | Data | Used for |
|---|---|---|
| **live** | the REST APIs of a Process Center / Process Server (lab https://<process-center-host>:9443, celladmin) through a dev-server or nginx proxy | ratifying every function against the real engine, functional tests |
| **demo** (public) | the same live mode against the lab Process Center reachable from the demo host (user decision 2026-09-11: no stubbed data) | https://headless.quickpod.org on the demo host |
| offline (optional) | stubbed APIs + data (fixtures captured from the lab, mutated in memory) | offline demonstrations only |

User decisions: Angular with all the bells and whistles (Material, standalone components, signals, lazy routes, guards,
interceptors, reactive forms, theming, animations, charts, unit + end-to-end tests); integrated sign-on; a sample process
application delivering headless tasks; everything ratified locally against the lab before stubbing; private repo
`dosvak/headless-process-portal`.

## 2. Headless task contract (sample application)

A user task of the sample application carries in its input data a business object **HeadlessForm**
`{title, description, fields: FormField[] {name, label, type (text | textarea | number | date | select | checkbox | radio), required, options ("a|b|c"), value, help}}`
plus the business data the form is about. The portal reads the task (`GET /task/{id}?parts=all`), renders the form, validates it,
and completes the task with `PUT /task/{id}?action=complete&params={...}` where the params are the task's output variables. The
process continues on the outputs (gateways). Every task of the sample app is implemented by a placeholder client-side human
service that is never rendered (Web Process Designer 8.6.2 offers no External Implementation artifact; documented deviation).

Sample process application **Headless Sample (HDLS)**, generated by `tools/build_headless_sample.py` (BAW workspace):

| Process | Inputs (start form) | Headless tasks (team) | Outputs / flow |
|---|---|---|---|
| Expense Approval | employee, amount, category, purpose, receiptDate | Approve expense (Managers): decision radio, comment; Reimburse expense (Finance): paymentReference, paidOn | approved -> reimbursement, rejected -> end |
| Customer Onboarding | customerName, email, plan | Verify documents (Operations): idVerified, addressVerified, notes; Activate account (Operations): accountNumber, welcomeEmailSent | all verified -> activation, else -> end (rejected) |
| Support Ticket | title, description, priority | Resolve ticket (Support): resolution textarea, rootCause select, timeSpent number; Confirm resolution (requester): satisfied radio, feedback | priority drives the due date; not satisfied -> back to Resolve |

Teams: Managers, Finance, Operations, Support (members: celladmin + lab users); processes exposed to All Users.

## 3. Architecture (Angular 22)

```
src/app
  core/        api/ (BpmApi interface, LiveApi, StubApi + fixtures + engine), auth/ (AuthService, guard, interceptor), state/ (signal stores),
               layout/ (shell, nav, header, notifications drawer), theme/
  features/    login, work (list, saved searches), task (detail, headless form), launch, instances (list, detail), dashboards, search,
               profile, teams
  shared/      form renderer (contract -> reactive form), data table, charts (Chart.js wrapper), pipes (dates, priority), dialogs
```
* API layer: one `BpmApi` interface; `LiveApi` calls `/rest/bpm/wle/v1` (+ `/bpm` v2 where useful) through the proxy, `StubApi`
  serves fixtures and mutates them (claim, complete, start, comments) so the demo behaves like the engine. The mode comes from the
  build configuration (`environment.mode`).
* Auth: login form -> credentials kept in session storage -> `Authorization: Basic` header by an interceptor; `GET /user/current`
  validates; 401 -> back to login. CSRF token fetched at login for the v2 family.
* Dev proxy (`proxy.conf.json`): `/rest`, `/bpm`, `/ops` -> https://<process-center-host>:9443 (self-signed accepted).
* Tests: Vitest unit tests (form renderer, stub engine, stores), Playwright end-to-end (live mode against the lab: sign-on, work
  list, claim, headless task completion, launch, instances, dashboards; demo mode: the same script against the stub).
* Deployment: `ng build --configuration production` -> static files -> `/var/www/headless.quickpod.org` on proc, nginx vhost (add-on,
  never touching the other vhosts) proxying `/rest/` to the engine host (configured in the vhost only), certbot certificate; DNS `headless.quickpod.org -> 15.204.161.174` (set by the user).

## 5. Decisions log

* 2026-09-10 - separate repo `dosvak/headless-process-portal`; Angular 22 with Material; sample headless tasks fully implemented.
* 2026-09-10 - only the process engine is used (no Process Portal artifact); all authentication and authorisation from the
  Process Center / Process Server.
* 2026-09-11 - the public demo connects to the real lab engine instead of stubs; host name headless.quickpod.org;
  the portal is scoped to the test application (HDLS) because product UI tasks are not headless; demo credentials shown on
  the login page (the lab accounts).
* 2026-09-11 - engine fact: `PUT /task/{id}?action=complete` maps the outputs only with `params` in the query string (a form body
  closes the task without the data); the legacy priority element of a generated BPD accepts only the default encoding on 8.6.2
  (non-default priorities are set at runtime through `action=update&priority=`).
* 2026-09-11 - CP4BA lab announced for 2026-09-12: docs/CP4BA.md (compatibility, sign-on, v2 mapping, external implementations, validation plan) and tools/cp4ba_probe.py prepared from the CP4BA tenant checks of 2026-09-04/05.
